# Iron Core: AI Commander

Браузерная RTS по брифу «Warcraft-like игра с ИИ-агентом, управляющим боевыми роботами, и голосовым управлением».
Игрок не ведёт каждого робота: он ставит задачи GenAI-агентам голосом или текстом. Агенты проектируют машины и планируют бой,
а игра считает физику, валидирует проекты и исполняет планы. Боты (инженер, тактик и вражеский генерал) думают **облачным LLM API**.

Стек: React 18 + TypeScript + Vite, Three.js (мультяшная изометрия), Tailwind, Web Speech API (ASR/TTS).

## Запуск

```bash
npm install
cp .env.example .env.local   # укажите LLM_PROXY_TARGET / LLM_API_KEY / LLM_MODEL
npm run dev
```

Откройте адрес из консоли Vite. На стартовом экране видно, к какой модели подключены боты.

### Готовая сборка из релиза

В релизе на GitHub лежит архив `iron-core-ai-rts-v0.2.0-dist.zip` со статической сборкой. Её можно отдать любым
статическим сервером, например `npx serve dist`. Серверного прокси `/api/llm` в статической сборке нет, поэтому LLM
подключается напрямую из браузера: ⚙ → провайдер, ключ и модель. Сервер модели должен разрешать CORS. Как
опубликовать сборку на Firebase Hosting, описано в разделе [«Публикация на Firebase Hosting»](#публикация-на-firebase-hosting).

### Подключение LLM

Есть два способа, оба OpenAI-совместимые:

1. **Серверный прокси (рекомендуется).** Dev/preview-сервер Vite проксирует `/api/llm/*` на `LLM_PROXY_TARGET`
   и сам подставляет `LLM_API_KEY` из `.env.local`. Ключ не попадает в браузер. При первом запуске игра сама выбирает прокси,
   если он настроен.
   - Локальная модель (oMLX/vLLM/LM Studio): `LLM_PROXY_TARGET=http://127.0.0.1:8000/v1`, `LLM_MODEL=Qwen3.6-35B-A3B-UD-MLX-4bit`.
   - Облако (OpenRouter, Qwen): `LLM_PROXY_TARGET=https://openrouter.ai/api/v1`, `LLM_MODEL=qwen/qwen3-30b-a3b-instruct-2507`.
2. **Напрямую из браузера.** ⚙ → выберите провайдера (OpenRouter·Qwen, Alibaba DashScope, Groq, OpenAI, Gemini,
   Anthropic, свой OpenAI-совместимый), вставьте ключ, загрузите список моделей и нажмите «Проверить подключение».
   Ключ хранится только в `localStorage` этого браузера.

Бриф советует быстрые недорогие модели семейства Qwen, поэтому по умолчанию стоит Qwen3 MoE. Для гибридных Qwen3 клиент
отключает скрытое «размышление» (`chat_template_kwargs.enable_thinking=false` / `enable_thinking` / `reasoning_effort`).
Иначе модель сжигает бюджет токенов и отвечает в разы медленнее. Без настроенного LLM агенты отвечают локальными
эвристиками, и UI помечает такие ответы как «локально».

## Как боты используют LLM

| Агент | Когда вызывается | Что возвращает | Что делает игра |
|---|---|---|---|
| **Болт**, агент производства | приказ игрока | конфигурация из каталога и/или производственные действия, компромисс, лимит стоимости | считает характеристики, проверяет слоты, массу, энергию, отдачу и лимит стоимости; при нарушении делает один раунд починки через LLM, затем локальную починку с объяснением; показывает «до/после» и ждёт «В серию / Отмена» |
| **Кобра**, агент управления | приказ игрока и **автономно** сразу по значимым событиям (тяжёлые потери, атака на базу или добычу, новая модель врага), не чаще раза в 8 с | план: стойка, дистанция, приоритет целей, порог отступления на ремонт, прикрытие добычи | игровой AI исполняет план между вызовами; план можно откатить или поправить вручную |
| **Генерал Ржавый**, AI-противник | полная сводка раз в ~30 с; быстрый пересмотр плана сразу по событиям боя, не чаще раза в 8 с | сводка: контр-конструкция, план, экономика, язвительная реплика (перехват); пересмотр: только план и короткая реплика | валидирует и применяет; при недоступности LLM работает классический AI на правилах |

Контекст каждого вызова короткий (бриф §10): роль, актуальные инструкции игрока, допустимые действия, компактная сводка
армии и экономики, разведданные (замеченные модели врага, сколько машин видно сейчас и когда был последний контакт),
5 последних существенных событий и каталог деталей. Действует туман войны: сторона видит только то, что видят её машины
и здания, лес закрывает обзор. Полная история и
покадровая телеметрия не передаются. Модель не назначает бонусов и не управляет движением роботов.

Реакция на бой. События одной атаки собираются ~1 с и уходят одним вызовом. Пока вызов в работе, новые события ждут его
и отправляются сразу после ответа. Пересмотр командира по событию короткий: без каталога и экономики, ответ ~100 токенов,
поэтому даже медленная локальная модель отвечает за секунды. Пока модель думает, игровой AI реагирует сам: если базу
обстреливают, машины рядом с домом (в том числе ждущие на точке сбора) идут на нападающего.

Очередь заказов. Агент может заказать здание или добытчика, на которые пока не хватает ресурсов. Так бывает с
подтверждённым предложением инженера или с решением LLM-командира. Тогда игра не отказывает, а ставит заказ в очередь
стороны. В очереди не больше трёх заказов, повтор того же заказа её не дублирует, а каждый заказ ждёт до 60 с игрового
времени. Заказ выполняется сам, как только хватает ресурсов и есть место или площадка. Но платит очередь только из того,
что останется после следующей боевой машины, поэтому выпуск армии не голодает. Агенты видят очередь одной строкой
сводки («ОЧЕРЕДЬ ЗАКАЗОВ: turret (base) — Нужно 120 металла, ещё 48 с»). Снятый по времени заказ попадает в строку
отказов. Заказы инженера видны в панели «Производство» с кнопкой отмены. Кнопки самой панели, как и раньше, строят
сразу или отказывают. Правиловый AI заказывает только то, на что хватает ресурсов, поэтому очередью не пользуется.

## Кампания

Игра идёт по уровням: победа открывает следующий, прогресс и рекорды хранятся в браузере. Семь уровней кампании
(`src/config/levels.ts`) вводят по одной новинке: лес и туман войны, лесные коридоры, топь, густую чащу, каменные гряды,
лесную стену с одними воротами перед базой противника. Дальше идёт бесконечный режим. Игрок всегда в одних условиях,
усиливается противник: доход, доступные шасси, гарнизон у штаба, прочность штаба и доктрина генерала. LLM-генерал
получает доктрину и разрешённые шасси в сводке. Сложность проверяет `tests/campaign.test.ts`: правиловый командир за
бирюзовых выигрывает первый уровень почти всегда, а седьмой редко.

## Режим «ИИ против ИИ»

Вторая кнопка на стартовом экране запускает матч без участия человека. За бирюзовых играет Командор Бирюзов, за
оранжевых — Генерал Ржавый. Оба — LLM-командиры с одинаковыми правилами: раз в ~30 с проектируют машины из каталога,
задают план армии и экономику и переругиваются в эфире, а по событиям боя быстро пересматривают план. Без настроенного LLM оба переходят на локальные правила.

- Командиры обращаются к модели по очереди, а не одновременно: локальный сервер обрабатывает запросы последовательно.
  Первым ходит тот, кто дольше ждал, так что предел частоты решений одинаков для обоих.
- Перед стартом можно дать Командору Бирюзову свои указания, до 500 символов. Они попадают в его системный промпт и
  повторяются в конце каждой сводки, так модель следует им заметно надёжнее. Это касается и полных сводок, и быстрых
  пересмотров плана. Генерал Ржавый указаний не видит. Текст сохраняется в браузере, а панель зрителя показывает
  действующие указания.
- Панель зрителя показывает обе стороны: реплики, источник решения (LLM или правила), серийную модель, план, армию,
  добытчиков, металл и штаб. Есть скорость ×1/×2/×4, кнопка «В меню» и итоги матча со сравнением сторон.
- Режим ничего не списывает с баланса AI-монет: это демонстрация. Расход токенов виден в панели монет.

## AI-монеты (бриф §10)

- Отдельный тестовый баланс (не металл и не энергия) и лимит расходов на матч (⚙ или панель монет).
- Детализация по четырём сервисам: агент производства, агенты управления, распознавание речи (ASR), синтез речи (TTS).
  AI-противник учитывается отдельной строкой и по умолчанию не списывается; его можно включить в тариф.
- Учитываются входные/выходные токены, секунды ASR/TTS, число вызовов, ошибки и задержки.
- Списание идемпотентно: ошибки и технические повторы не оплачиваются дважды.
- Игра заранее предупреждает, когда монеты на исходе. После исчерпания армия продолжает последний допустимый план
  обычным игровым AI.
- Частота автономных AI-решений одинакова для обоих участников: больший баланс не даёт более частого управления.

## Управление

Камера: перетаскивание мышью, колесо для масштаба, WASD или стрелки, клик по мини-карте. Приказы — микрофон или текст.
Голосом можно сказать «в серию», «испытай» или «отмена» для текущего проекта.

**Испытание конструкции до производства** (открытое решение брифа §9): кнопка «Испытать» в панели конструктора прогоняет
безголовые бои 4×4 нового проекта против модели врага, замеченной разведкой (без разведданных — против базовой модели).
Бои идут на трёх дистанциях с разными флангами на реальном боевом коде: броня, нагрев, развёртывание, отдача.
Результат: доля побед, длительность боя, оставшаяся прочность. Для сравнения показываются текущая серия и вариант
«равный бюджет», то есть несколько дешёвых машин против одной дорогой. Испытание бесплатно по AI-монетам: это игровая
симуляция, а не inference. Зато вердикт приходит через 5 секунд игрового времени, так что игрок выбирает между темпом
и информацией, а «В серию» можно нажать, не дожидаясь стенда. Добытчики, электростанции, второй завод и размер
партии задаются в панели «Производство» или через приказ инженеру.

## Покрытие брифа

| Раздел | Реализация |
|---|---|
| 1–2. Концепция и цикл | добыча → партия → столкновение → приказ агенту → новая партия; изменения идут только в следующие партии |
| 3. Экономика | кристаллы с 4-го уровня (детали второго уровня, тяжёлое шасси, лаборатория); здания строят добытчики (на время стройки они не добывают); турель, ремонтный док, радарная вышка, пункт приёма, лаборатория и артиллерийская турель на площадках у базы и на передовой; металл с площадок и обломков; компоненты из металла (фабрикатор штаба); энергосеть базы ограничивает заводы, добычу, фабрикатор и ремонт; безопасные и центральные месторождения |
| 4. Ограничения робота | масса и разгон, бортовая энергия, слоты (объём), нагрев и перегрев, устойчивость к отдаче, развёртывание осадных орудий, цена и время сборки |
| 5. GenAI-агенты | конструктор с подтверждением, сравнением, компромиссом и уточнением; тактические агенты; текст как альтернатива голосу |
| 6. Бой и победа | волны «стенка на стенку», роли (артиллерия держится за линией, быстрые обходят и бьют добычу), турель штаба; победа — уничтожение командного центра |
| 7. Визуал и UI | мультяшная изометрия: песок, рощи и каменные гряды, бирюза против оранжевого, видимые модули на моделях, ресурсы и мощность, мини-карта, очереди заводов, панель конструктора с портретом, микрофоном, распознанной фразой, превью и полосами «до/после» |
| 8. Прототип | кампания из семи карт и бесконечный режим, две базы, игрок против AI, лёгкое/среднее/тяжёлое шасси, 3 брони, ближнее и дальнее оружие, 2 привода |
| 10. Монетизация | см. «AI-монеты» |

Открытые решения брифа, принятые по умолчанию: уничтожение (а не захват) базы; размер партии 1–5 (по умолчанию 3);
AI-противник не входит в тариф игрока; автономные пересмотры сразу по событию боя, но не чаще раза в 8 с на сторону; испытание конструкции до производства
доступно и стоит 5 с игрового времени.

## iOS-приложение (модель на устройстве)

В `ios/` лежит приложение для iPhone и iPad. Внутри та же игра в WKWebView, но агенты думают **моделью Apple
на устройстве** (фреймворк Foundation Models, Apple Intelligence, Neural Engine): без сети, ключей и AI-трафика.

```bash
npm run build:ios                 # собрать игру в ios/Web (фиксированная ширина раскладки, без веб-шрифтов)
open ios/IronCore.xcodeproj       # Xcode 26+, схема IronCore; для iPhone укажите свою команду подписи
```

- **Требования.** iOS 26+, устройство с Apple Intelligence (iPhone 15 Pro и новее), Apple Intelligence включена.
  На других устройствах игра работает, а агенты переходят на локальные правила.
- **Русский язык.** Модель Apple не поддерживает русский. Для неё агенты получают английские промпты
  (`src/ai/promptsEn.ts`). Русские фрагменты — приказ, события, названия моделей, указания штаба — переводит на
  английский Apple Translation на устройстве. Поля ответа, которые видит игрок (реплика, компромисс, насмешка,
  суть плана, имя модели), переводятся обратно на русский. Языки система предлагает скачать при первом запуске.
  Без перевода промпты уходят как есть, а ответы остаются на английском.
- **Мост.** `window.webkit.messageHandlers.ironcoreLLM` (`ios/IronCore/OnDeviceBridge.swift` ↔
  `src/ai/llm/nativeBridge.ts`): `status`, `generate`, `translate`. Запросы к модели идут по одному, окно
  контекста — 4096 токенов.
- **Экран.** Ландшафт, вне зоны Dynamic Island. На низких экранах «Производство» и «План армии» свёрнуты
  до сводки и раскрываются по нажатию.
- **Симулятор.** Модель в симуляторе берётся с Mac: нужна включённая Apple Intelligence на самом Mac. Перевод в
  симуляторе не работает (`unsupportedLanguagePairing`). Отладочная сборка принимает аргументы запуска
  `-autotest` (короткий матч «ИИ против ИИ» на модели устройства с отчётом в консоль) и `-autoplay`:

```bash
xcrun simctl launch --console-pty booted com.ironcore.aicommander -autotest
```

## Публикация на Firebase Hosting

`npm run build` собирает статику: `dist/index.html` и файлы с хешем в имени в `dist/assets/`. В `firebase.json`
указано `public: "dist"`. Файлы из `assets/` кешируются на год (`immutable`), а `index.html` отдаётся с `no-cache`,
поэтому новая версия видна сразу после деплоя. SPA-rewrite не нужен, у игры один адрес `/`. iOS-сборка это не
затрагивает: `npm run build:ios` пишет в `ios/Web`, а Firebase берёт только `dist/`.

Firebase CLI ставить не нужно. Скрипты вызывают `firebase-tools@15.33.0` через `npx`, любую команду CLI можно
запустить как `npm run firebase -- <команда>`.

1. **Один раз: проект и вход.** Создайте проект в [консоли Firebase](https://console.firebase.google.com/) и
   включите в нём Hosting (Build → Hosting → «Get started»). Хватает бесплатного тарифа Spark. Затем войдите в CLI,
   откроется браузер:

   ```bash
   npm run firebase -- login
   ```

2. **Id проекта.** Впишите его в `.firebaserc` вместо `YOUR_FIREBASE_PROJECT_ID`. Посмотреть id своих проектов:

   ```bash
   npm run firebase -- projects:list
   ```

3. **Деплой на основной сайт** `https://<id>.web.app`:

   ```bash
   npm run deploy
   ```

4. **Превью-канал.** Временный отдельный адрес, основной сайт не меняется. CLI напечатает ссылку вида
   `https://<id>--preview-<хеш>.web.app`:

   ```bash
   npm run deploy:preview
   ```

   Это канал `preview` на 7 дней. Свой канал и срок (не больше 30d):

   ```bash
   scripts/deploy.sh preview my-feature 3d
   ```

   Удалить канал раньше срока:

   ```bash
   npm run firebase -- hosting:channel:delete preview
   ```

Шаги 2–4 требуют входа из шага 1. Перед загрузкой скрипты собирают игру и запускают `scripts/check-deploy.mjs`.
Проверка останавливает деплой, если в `.firebaserc` остался шаблон или если в `dist/` попал файл `.env*` либо
значение секретной переменной: имя содержит `KEY`, `TOKEN`, `SECRET` или `PASSWORD`, значение взято из `.env.local`
или окружения. Само значение не печатается, только имя переменной и файл.

Проверить `firebase.json` без входа: эмулятор Hosting отдаёт `dist/` с теми же заголовками на
http://127.0.0.1:5050 (проект `demo-…` не требует аккаунта):

```bash
npm run build && npm run firebase -- emulators:start --only hosting --project demo-iron-core
```

### LLM на хостинге

- **Серверного прокси нет.** `/api/llm` — это middleware dev/preview-сервера Vite. Rewrites Firebase Hosting ведут
  только в Cloud Functions или Cloud Run, на произвольный URL их не направить. При запуске игра запрашивает
  `/api/llm/status`. На хостинге он отвечает 404, и кнопки «Серверный прокси» в ⚙ нет. Если прокси уже выбран в
  сохранённых настройках, кнопка остаётся с пометкой «нет на этом сайте: только npm run dev / preview».
- **Облачные провайдеры** работают напрямую из браузера: ⚙ → провайдер → ключ. Каждый игрок вводит свой ключ, он
  хранится в `localStorage` его браузера для этого сайта и в сборку не попадает. OpenRouter, DashScope, Groq,
  OpenAI, Gemini и Anthropic пропускают CORS-запросы с чужого домена (проверено 23.10.2026).
- **Локальная модель** (oMLX на `http://127.0.0.1:8000/v1`, CORS `*`): провайдер «Локальный / свой
  OpenAI-совместимый», ключ oMLX — в поле «API-ключ». `127.0.0.1` — это компьютер игрока, поэтому так работает
  только на машине, где запущен сервер модели. Сайт открыт по HTTPS, а модель по HTTP. Chrome, Edge и Firefox
  считают `127.0.0.1` доверенным адресом и такой запрос пропускают. Chrome может спросить разрешение на доступ к
  устройствам локальной сети, его нужно дать. Safari может заблокировать запрос как смешанный контент, тогда
  откройте сайт в Chrome или играйте через `npm run dev`.
- **Ключ на сервере для всех игроков** потребует своего бэкенда, в репозитории его нет. Вариант: Cloud Function
  (тариф Blaze) или сервис Cloud Run с логикой `llmProxy` из `vite.config.ts`. Это только `/status`, `/models` и
  `/chat/completions`, ключ хранится в Secret Manager. Затем нужен rewrite в `firebase.json`:

  ```json
  "rewrites": [{ "source": "/api/llm/**", "function": { "functionId": "llm", "region": "europe-west1" } }]
  ```

  Такой прокси сможет вызвать кто угодно, и платить за запросы будете вы. Без App Check и лимитов запросов его
  лучше не открывать.
## Анонимная статистика (Firebase Analytics)

Игра может отправлять анонимную статистику в Google Analytics 4 через Firebase Analytics (проект `iron-ai-rts`).
Пока игрок не согласился, SDK не загружается и запросов нет.

**Согласие.** На стартовом экране игра один раз спрашивает «Поможете улучшить игру?». До ответа и после «Не надо»
статистики нет. Ответ хранится в `localStorage` (`ironcore_analytics_v1`), передумать можно в ⚙ → «Анонимная
статистика». Если браузер шлёт Do Not Track или Global Privacy Control, игра не спрашивает, но переключатель в
настройках работает.

После «Разрешить» игра загружает отдельный чанк `firebase-*.js` (около 15 КБ gzip) и gtag.js. В Consent Mode
`analytics_storage` разрешён, а рекламные `ad_storage`, `ad_user_data` и `ad_personalization` всегда запрещены.
Google Signals и персонализация рекламы выключены (`allow_google_signals: false`,
`allow_ad_personalization_signals: false`). Отказ в настройках останавливает сбор и удаляет cookie `_ga*` и базу
установки Firebase в браузере.

**Почему с cookie и по согласию.** Варианта без cookie у Firebase Analytics нет. GA4 игнорирует
`client_storage: 'none'`: проверено в браузере, gtag всё равно ставит `_ga`. Без cookie можно работать только через
`analytics_storage: 'denied'`, но тогда события уходят пингами без cookie, и GA4 почти не показывает их в отчётах.
Кроме того, Firebase в любом режиме хранит в IndexedDB идентификатор установки. Поэтому статистика включается только с
согласия, а cookie `_ga` и идентификатор ставятся уже после него. Зато видны вернувшиеся игроки, удержание и
прохождение кампании за несколько сессий.

Режим задаётся одной константой `CONSENT_POLICY` в `src/analytics/index.ts`. `'opt-in'` (по умолчанию) — выключено,
пока игрок не согласится. `'opt-out'` — включено сразу, вместе с cookie, игрока не спрашивают, переключатель в
настройках выключает. Данных при opt-out больше, но cookie ставится без согласия, а для игроков из ЕС это рискованно.
При Do Not Track или Global Privacy Control статистика и в этом режиме выключена, пока игрок сам её не включит.

**Что собирается.** Только числа, да/нет и значения из фиксированных списков. Схема событий лежит в
`src/analytics/events.ts`. `track()` по типам не принимает произвольную строку, а событие с неизвестным параметром
или значением вне списка отбрасывается целиком.

| Событие | Параметры | Зачем |
|---|---|---|
| `match_start` | `mode` (human/spectator), `level`, `endless`, `lang`, `provider`, `provider_kind`, `llm_ready`, `enemy_llm` | Сколько матчей начинают, на каких уровнях и языках, с какой моделью; доля игр без настроенного LLM |
| `match_end` | `mode`, `level`, `endless`, `outcome` (won/lost/restart/quit/closed), `duration` (корзина), `units_built`, `units_lost`, `kills`, `harvesters_lost` | Воронка уровня: победы, поражения, перезапуски и брошенные матчи; длина матча; баланс |
| `llm_match` | `mode`, `level`, `provider`, `provider_kind`, `calls`, `errors`, `fallback_pct`, `latency` (корзина), `err_network`, `err_timeout`, `err_parse`, `err_auth`, `err_rate_limit`, `err_server`, `err_http`, `err_device`, `err_not_configured`, `err_no_coins`, `orders`, `orders_queued`, `orders_refused` | Надёжность LLM за матч одним событием: ошибки по видам, доля откатов на эвристики, задержка, судьба экономических приказов агентов |
| `campaign_progress` | `level`, `unlocked` | Прохождение кампании |
| `level_pick` | `level`, `unlocked` | Переигрывают ли открытые уровни |
| `agent_order` | `agent` (engineer/tactician), `input` (text/voice/quick) | Как часто и как отдают приказы агентам |
| `proposal_decision` | `decision` (confirm/cancel), `source` (llm/fallback), `has_design`, `actions` | Принимают ли предложения инженера, от модели и от эвристик |
| `design_change` | `chassis`, `source` | Какие шасси идут в серию |
| `design_trial` | `cached` | Пользуются ли испытательным стендом |
| `plan_change` | `field` (stance/range/target/retreat/guard/revert), `stance`, `range`, `target` | Как правят план армии вручную; ползунок даёт одно событие, а не по шагу |
| `building_built` | `building` | Какие здания игрок достраивает |
| `voice_input` | `result` (final/stopped/denied/error/unsupported/no_coins) | Работает ли голосовой ввод |
| `language_change` | `lang`, `in_match` | Какие языки нужны |
| `llm_test` | `provider`, `provider_kind`, `result` (ok или вид ошибки) | Где игроки спотыкаются при подключении LLM |

В режиме «ИИ против ИИ» `won` и `lost` относятся к бирюзовой стороне. `closed` значит, что вкладку закрыли посреди
матча; такое событие отправляется по возможности. Свойство пользователя `highest_level` хранит самый дальний открытый
уровень. GA4 сам добавляет просмотр страницы и сессию, случайный идентификатор клиента из cookie `_ga`, идентификатор
установки Firebase, язык и разрешение экрана браузера и примерную страну по IP. Сам IP-адрес GA4 не хранит.

**Что не собирается.** Идентификатор пользователя и email, тексты чата и приказов, указания командирам, ответы и
реплики моделей, названия моделей, адреса серверов (base URL), ключи. Провайдер уходит только как id из списка
(`openrouter`, `custom` и т. п.) и вид: `none`, `device`, `local`, `proxy`, `cloud`. Ошибки LLM уходят только видом
(`timeout`, `auth`, `rate_limit`…), без текста.

**Где выключена.** В `npm run dev`, в vitest, в iOS-приложении (сборка `--mode ios` вообще не содержит SDK) и на
localhost.

**Проверка в DebugView.**

```bash
npm run build
npx vite preview
```

Откройте `http://localhost:4173/?analytics_debug=1` и нажмите «Разрешить» внизу стартового экрана. Флаг включает сбор
на localhost и в dev, помечает события `debug_mode` и пишет каждое в консоль браузера: `[analytics] match_start {…}`.
В консоли Firebase → Analytics → DebugView события появляются через несколько секунд. Сами запросы видны во вкладке
Network: `region1.google-analytics.com/g/collect`, параметры событий начинаются с `ep.` и `epn.`.
В отчётах GA4 параметры событий видны только после регистрации: Admin → Custom definitions, строковые параметры как
custom dimensions, числовые как custom metrics. До этого они есть только в DebugView и в экспорте в BigQuery.

**Ключ Firebase.** `apiKey` в `src/analytics/firebase.ts` — публичный идентификатор веб-приложения, а не секрет, как
ключи LLM. Ограничьте его в Google Cloud console: APIs & Services → Credentials → «Browser key (auto created by
Firebase)» → Application restrictions → HTTP referrers. Укажите домены, где лежит игра (`iron-ai-rts.web.app/*`,
`iron-ai-rts.firebaseapp.com/*`, свой домен), и при необходимости `localhost:4173/*` для проверки. В API restrictions
аналитике нужны Firebase Installations API и Firebase Management API.

## Тесты

```bash
npm test             # юнит-тесты и безголовая симуляция матчей
npm run test:live    # живые вызовы агентов к LLM из .env.local (LLM_PROXY_TARGET/LLM_API_KEY/LLM_MODEL)
```

Живая проверка кампании: приказы инженеру на новые механики и матчи «ИИ против ИИ» на модели по уровням. Число игровых
секунд и уровни задаются переменными, полный отчёт пишется в JSON:

```bash
LLM_LIVE=1 CAMPAIGN_LIVE_LEVELS=3,5,6 CAMPAIGN_LIVE_SEC=420 CAMPAIGN_LIVE_REPORT=report.json npx vitest run tests/campaign-live.test.ts
```

В конце матчей тест печатает долю отказанных экономических приказов моделей: отказанных сразу и снятых из очереди
позже.
